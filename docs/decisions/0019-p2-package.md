# 0019 P2 整合包：成品快照单独成目录，测试重命名防重名

- 日期：2026-10-09
- 阶段：P2_Coding（收官增补，不占阶段机制）
- 状态：已采纳

## 背景

P2 的十一阶段走完，全部功能散在 `_01`–`_11` 十一个**自包含**目录里（P2 的组
织约定：阶段间不共享代码，每阶段带一份完整 `harness/` 副本 + 该阶段新增的顶层
模块）。这对"学习/验收"是对的——每个阶段的边界、README、测试都独立可读；但想
"把 P2 的成品整体拿去用/给别人看"就得先做一道题：**到底哪份副本是最新的**？
只有 `_11` 是全集（它的 `harness/` + 顶层包叠起来就是全部机制），但目录名
（`_11_Session_Follow`）与文档语境都写着"本阶段的机制"，不像一个可交付的成品。

## 决策

**1) 整合包 = `P2_Coding/mini_harness/`，内容是 `_11` 完成态的拷贝**：
P2 的机制演化是单线的（`_01 → … → _11`，后一阶段复制前一阶段的基线并只加一个
机制），所以 `_11` 的代码树**就是**P2 全部功能的集成——它已经是整合结果，
整合包只是把它换一个有交付意义的名字和位置。不重新拼装、不挑选文件，
"拷贝 `_11` 完成态"是唯一规则（也因此可机械重放）。

**2) 定位是"快照"，不是开发位置**：阶段目录是开发历史（含教学注解、决策记录
指向、逐阶段的 README 语境），整合包是成品。**后续修改在阶段/新阶段里做，
整合包在里程碑处重新生成**——把这一条写进整合包 README 的顶部，避免以后
"两份代码该改哪份"的歧义（与 0005 里"副本而非共享包"的 P1 教训同源：
接受副本的漂移风险，用"快照 + 明确的开发位置"划定纪律）。

**3) 测试随包，文件名加前缀**：拷贝 `_11` 的 7 个测试文件并重命名
（`test_session_follow_*.py` → `test_mini_harness_*.py`、`test_p2_webui.py` →
`test_mini_harness_p2_webui.py`）。**为什么必须重命名**：pytest 的 rootdir 模式下
把 `P2_Coding` 下所有测试收集到同一 session 时，**同名模块会被 dedupe**
（"import file mismatch" 是轻的，更糟的是静默只跑一份）——阶段目录的
`test_session_follow_unit.py` 与本包的同名文件会直接冲突。前缀命名让 829 个
用例在全量运行下互不干扰（实测通过）。

**4) 文本引用规整为包内语境**：拷贝后把路径指引类引用（"用法（在
`_11_Session_Follow` 目录下）"、"运行：cd `P2_Coding/_11_Session_Follow`"、
启动器注释、conftest 首行）改成 `mini_harness`；**机制性引用保留**（"来自
`_02_Prompt_Context` 的机制"这类是真实的演化出处，改掉反而丢失信息）。

**5) 门禁纳入整合包**：`scripts/check.py` 的检查列表加一项 `mini_harness`
（存在才检查——便于单独 checkout 某阶段时不为难）。整合包与阶段同标准验收：
ruff + 66 用例全绿。

## 备选与排除理由

1. **重新手工拼装一份**（从各阶段挑最新文件合成）。排除：P2 的阶段是单线演化，
   `_11` 已经包含全部机制；手工拼装只会引入"挑错版本"的风险，且不可机械重放。
   拷贝 `_11` 完成态这条规则可以一句话写清、随时重新执行。
2. **就地给 `_11` 改名/加 README 说明"这是全集"**。排除：会破坏阶段命名序列
   （`_01`–`_11` 的编号本身是学习路线的索引，根 README/学习计划都指向它），
   也丢掉了"开发历史目录"与"成品快照"的物理区分。
3. **弄成可 `pip install` 的包（加 `pyproject.toml` + 打包入口）**。排除：P2 的
   pyproject 明确"不做 setuptools 打包"（阶段式工作区约定）；分发形态是路线图
   里 P6（SDK 包）的题目，现在做会越界。整合包只需"`cd` 进去能跑"——它是个
   **目录**，不是发行物。
4. **测试不拷贝、只留 `_11` 的**。排除：整合包要能独立验收（"拿去哪都能自证"），
   依赖别的目录的测试就不自包含；重命名成本只有一次（7 个文件）。

## 后果

- 约束：整合包内任何"路径指引"类文档与阶段目录不同（指向 `mini_harness`），
  重新生成时需重放这套规则（见整合包 README 顶部的"快照"说明）。`harness/`
  冻结约定在整合包里继续成立（它也是 `_11` 的冻结基线）。
- 收益：**P2 全部功能有了单一定位**——`cd P2_Coding/mini_harness` 后
  pytest / chat / serve / attach / webui 五个入口齐备；66 用例随包自证；
  门禁全绿；全量 829 用例（含阶段目录）无重名冲突。
- 债务与后续：
  1. **快照会漂移**：整合包在里程碑处重新生成；若阶段目录有后续修改而整合包
     未重生成，以阶段目录为准（纪律写在两边 README）。
  2. **`_11` 里仍有一批"阶段语境"的陈旧引用**（如 `chat.py` 的 `_08` 字样、
     早期阶段的机制说明）——那是开发历史的一部分，保留原样；只有整合包里
     规整为成品语境。若将来清理 `_11` 的文档，两者会有一次并轨。
