# 0006 提示词装配：有序 section 注册表 + 作用域遮蔽

- 日期：2026-10-08
- 阶段：P2_Coding/_01_Prompt_Sections（学习计划 M4 第一步）
- 状态：已采纳

## 背景

P1 里系统提示词是一整个写死的字符串常量（`DEFAULT_SYSTEM_PROMPT`），在
`MiniHarness.open` 处一次性写进 `session/start`。它有三个问题：

1. **不可组合**：想调整"角色"那一段，得在一整段文本里找到位置改；不同会话想要不同
   的角色/风格，只能在调用处整段重传。
2. **不可局部替换**：没有"节"的概念，也就没有"只换工具约定、不动风格"这种操作。
3. **为后续机制留不下接口**：M4 的目标是"提示词可组合、可追溯、可重建"，
   但一个字符串既没有结构，也没有名字，无法在此基础上做运行时插值（`_02`）
   与来源追溯（`_03`）。

学习计划 M4 明确要求"section 注册表（有序、支持作用域覆盖）"，dsh 的
`system-prompt` 也是按 section 组装的。继续用字符串常量会把后续阶段堵死。

## 决策

引入三个小对象，把"一节提示词"变成一等公民：

- **`Section`**（`harness/prompt/section.py`）：一节提示词 = `name` + `content` +
  `source`（来源）+ `title`（可选）。`frozen=True`，构造后不可变；空名字 fail loud；
  想"改内容"就注册一个**新的**同名 Section（遮蔽），而不是就地修改。
- **`SectionRegistry` + `SectionScope`**（`registry.py`）：两层结构。基础层按注册顺序
  有序、重名报错；作用域覆盖层叠加其上——**同名遮蔽（保持原位）、未同名追加到末尾**，
  撤下（`drop`/`close`）后基础层自动恢复。
- **`PromptAssembler`**（`assembler.py`）：纯粹按来源顺序把各节正文**拼接成文本**
  （分隔符可配）。它对来源只读，因此既能接基础注册表，也能接作用域覆盖层。

装配点只有一处：`MiniHarness.open` 的 `system_prompt` 参数，接受
`str | PromptAssembler | None`（`None` 走内置默认装配器，`str` 向后兼容，
`PromptAssembler` 是 M4 主路径）。

排序规则是刻意的：**遮蔽同名 section 时保持它在基础层的位置**。这让"覆盖某节内容"
不会打乱整体结构——提示词的骨架由基础层决定，作用域只换血肉、不改骨架。

## 备选与排除理由

1. **直接上模板引擎（Jinja2 等）**。排除：模板解决的是"填空与循环"，而本阶段的核心是
   "**可组合 + 可遮蔽 + 可追溯**"的结构。引模板引擎会把注意力引向语法，且遮蔽语义
   （most-specific-wins）还得自己实现；而 `_02` 的变量插值只需要三四个占位符，届时
   一个几十行的插值函数就够了，不必背一个依赖。
2. **用"有序列表"存 section（不用名字）**。排除：没有名字就无法**按名遮蔽**，
   也就无法在不改动基础层的前提下做局部定制——这恰是铁律 #4 要的性质。
3. **用普通 dict 当注册表，遮蔽靠"写时覆盖"**。排除：写时覆盖会**篡改基础层**
   （基础层那条被删掉了），撤下作用域就无法恢复。本方案选择"解析时遮蔽"：
   基础层始终完整，作用域只是解析期的一层滤镜，回卷是天然无副作用的。
4. **作用域同名注册也报错**。排除：作用域的意义就是"允许覆盖"，同层内反复调整某节
   内容（如按顺序尝试几种措辞）应被允许；报错只保留给基础层（那是共享底座，必须稳定）。

## 后果

- 约束：`harness/prompt/` 是**纯逻辑**——只吃字符串、吐字符串，不依赖 harness 其它子包；
  装配点集中在 `MiniHarness.open` 一处；基础层重名 fail loud。
- 收益：提示词可按节替换/遮蔽/追加；15 个新用例覆盖顺序、重名、遮蔽、追加、恢复、
  close、分隔符、接线（共 37 用例含基线）；`demo.py` 新增第 0 节直观演示装配与回卷。
- 债务：`source` 目前只是打标签，尚未被消费——`_03_Prompt_Trace` 会用它做
  `--dump-prompt` 的来源展示；section 内容仍是静态文本，`_02_Prompt_Context` 才引入
  `{{cwd}}` 等变量插值与"每 step 渲染"。
- 后续：`_02` 在同一份注册表上加插值；`_03` 加来源追溯与"可由日志 + 装配器重建"的断言。
