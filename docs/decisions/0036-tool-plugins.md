# 0036 工具插件化：底座与内容分开（一件事一个插件）

- 日期：2026-10-16
- 阶段：P3_Coding `_06_Tool_Plugins`
- 状态：已采纳

## 背景

用户的要求（原话）：

> 将目前的 tools 拆分成，tools 管理插件（基础），以及可以不同的 tool 插件，
> 不同的 tool 插件之间应该尽量解耦避免依赖，用户可以在 tools 管理插件的子页面
> 下管理停用启用或卸载 tool，同时，ai 本身也应该可以编写新的 tool，
> 然后自动操作 tools 管理插件把 tool 激活

当时的 `plugins/tools.py` 是一个**合体插件**：`inject fs` + 在 `setup` 里注册
八件工具。它同时扮演两个角色：

1. **工具面**（服务 `tools`：模型的手）——这是地基，agent 依赖它；
2. **工具内容**（给模型哪些工具）——这是策略，装配方的取舍。

## 决定

拆成两层，用**同一个注册表**连起来：

    plugins/tools.py        只做底座：提供**空的** ToolRegistry
                            + tool-admin（台账/开关/装卸）
                            + 两件自我管理工具（list_tools / install_tool）
    plugins/tool_calc.py    一件工具一个插件（或一类）
    plugins/tool_fs.py
    plugins/tool_search.py
    plugins/tool_shell.py

工具插件**只依赖 `tools` 服务与自己需要的能力插件**，互相之间没有依赖。

## 为什么

**理由一：底座是地基，内容是策略——生命周期完全不同。**

`tools` 被换掉/停用，整个应用就不成立（模型没有手）；而"要不要给检索能力"
是一次装配取舍，随时可改。合体意味着改后者要动前者，且换 fs 会把整个工具面
拆掉（tools 不得不 `inject fs`）。拆开后 tools 对 fs 只声明 `optional`——
实测：换 fs 时退位的只有 tool-fs / tool-search，工具面与 agent 照常，
fs 回来后它们自动回位（`test_swapping_fs_plugin_deactivates_and_reactivates_dependents`）。

**理由二：管理需要"归属"。**

面板要能回答"这件工具哪来的、我该卸谁"。所以登记必须**署名**：`owner` 是
`register()` 的必填参数（写历史：漏写当场报错）。停用作用于**工具**（可见面），
卸载作用于**插件**（归属者）——两个动作的语义因此干净且不重叠。

**理由三：模型自己写工具，要求"写一件工具"足够便宜。**

合体形态下写工具要凑三处（参数模型 + 定义 + 实现），且要改同一个大文件。
拆开后新增 `components/tools/declarative.py`：一个 `@tool` 函数就是一件工具，
签名即参数表、文档串即说明。`install_tool` 从工作区读一段 `.py` 就能装进去
（经人工审批）——这条路在浏览器里实测走通（模型写 → 人看源码批准 → 装载 →
下一轮调用成功）。

## 代价（如实记下）

- **多了一层间接**：找一件工具的实现要先去 `plugins/tool_*.py`，
  不像原先"全在一个文件里"一目了然。缓解：`list_tools` 与 `/tools` 都按
  owner 分组，归属是显式的；
- **`install_tool` 让"模型能改自己的手"**：因此它必须带审批，且是
  **fail-closed**（没有审批策略就拒绝）。这条边界写在 `components/tools/gate.py`；
- **工具间不能互相调用**：原先在同一个 `setup` 里可以互相引用实现
  （如 search 复用 read 的实现）。现在它们只能共享**能力服务**（fs），
  要复用实现就得把那部分提到构件层。代价换来的是"装卸互不牵动"。

## 备选方案与否决理由

**A. 不拆，只加"停用"开关。**
用户明确要"不同的 tool 插件"，且要求"解耦避免依赖"——只加开关不解决
"换 fs 拆掉整个工具面"和"新增工具要改同一个文件"这两件事。

**B. 工具插件之间声明依赖（一个工具插件复用另一个的工具）。**
工具调用不该走"插件 A 调插件 B"这条路：那会让装卸顺序、丢失依赖、循环依赖
全都进来。要复用就共享服务（fs / subprocess）或把实现提到 components 层。

**C. 停用 = 卸载再重装。**
丢掉了"只影响可见面"这件事（重装会重跑整个 setup、牵动依赖链），而且卸载再
重装之间工具是**真的没了**（另一个并发路径可能正需要它）。开关放在注册表上
是更小、更准的一刀。
