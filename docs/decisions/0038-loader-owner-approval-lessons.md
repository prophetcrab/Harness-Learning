# 0038 源码即插件：入口判据、署名与审批预览的三处实测教训

- 日期：2026-10-16
- 阶段：P3_Coding `_06_Tool_Plugins`
- 状态：已采纳

## 背景

`_06` 的核心是"**模型自己写工具**"：它写一个 `.py` 文件，`install_tool` 把它
装成插件。浏览器实测里走通了这条全流程，也顺带挖出三个只在**真跑**时才现形的
问题。它们不是同一个 bug，但都指向同一条教训：**从"一段源码"到"一件能用的
工具"这条路，每一步的判据都必须是显式的，不能靠"看着像"。**

## 三处教训

### ① 入口判据：类对象**有** `setup` 方法

`kernel/loader.py` 原先的判据是：

    if callable(obj) and not hasattr(obj, "setup"):
        instance = obj()          # 当成工厂函数
    else:
        instance = obj            # "已经是实例"

模型写的插件是最自然的形态（entry 指定类名）：

    class WordCountPlugin:
        def setup(self, ctx):     # ← 类对象本身就有这个方法
            ...

于是 `hasattr(cls, "setup")` 为真，**类**被当成实例直接交给内核，装载时报
`setup() missing 1 required positional argument: 'ctx'`。模型在浏览器里第一次
装就踩到了。

**判据改成**：`isinstance(obj, type)` → 一定实例化；非类的可调用对象（工厂函数）
→ 调用；只有真正的插件**实例**直接用。

**一般化的教训**：鸭子类型在"方法归属"这类问题上会失灵——`hasattr(cls, name)`
对类对象永远为真（方法在类上）。判据要问的是"这是不是**一个实例**"，
那就得看它是不是 `type` 的实例，而不是看它有没有那个方法。

### ② 署名：把"应该写"变成"不写就报错"

工具面要能被管理（按 owner 分组、按 owner 卸载），所以每件工具都得说清自己
是哪来的。原先这只是一个**约定**（写注释、写在文档里）——而约定会被漏掉：
`_06` 加的四件工具插件一开始都忘了传。

**做法**：`register(definition, func, *, owner)` 的 `owner` 必填，空串/空白当场
`ValueError`。这与决策 0031（把约定变成不变量）是同一取向：**漏写要当场响**，
而不是留个空字符串等着管理面板画出一个没有归属的分组。

### ③ 审批预览：清单会被忘记同步 → 让**工具自己**声明

审批卡片的价值在于"人能看到自己要批准什么"。原先预览逻辑在审批插件里维护
一张工具名清单：

    if tool_name not in ("install_plugin", "write_file", "edit_file"):
        return None        # 不给预览

`_06` 新加的 `install_tool` 也是"安装类"工具（要人审源码），但**不在清单里**
→ 审批卡片是空的。浏览器里当场看到：模型要装工具，卡片上只有一行理由，
**人等于盲批一段即将进入进程的代码**。

**做法**：`ToolDefinition.review_path_arg`（"审批时看哪个参数指向的文件"），
`install_plugin` / `install_tool` 各自声明 `review_path_arg="path"`；审批插件
按声明读文件。**少一张需要人工同步的清单**——这正是这个项目反复出现的模式：
把"两处需要记住同步"变成"一处声明"。

## 决定

1. `kernel/loader.py` 的入口判据用 `isinstance(obj, type)`（不是 `hasattr`）；
2. `ToolRegistry.register` 的 `owner` 必填、空值 fail loud；
3. 审批预览由 `ToolDefinition.review_path_arg` 声明驱动，不在审批插件里维护
   工具名清单。

三条都配了回归测试，且**反向验证过**（把修复撤掉，对应用例确实变红）。

## 代价

- `owner` 必填让"临时注册一件工具"（测试里、实验脚本里）多写一个参数。
  接受：显式署名的收益（可管理、可审计）大于这点啰嗦；测试里的桩件写
  `owner="demo"` 也顺便说明了它的来源；
- `review_path_arg` 是"参数名"约定：工具改参数名时要记得改它。这是**同一处**
  声明（定义就在旁边），比跨文件清单安全得多；写错的后果是"预览不显示"，
  而不是"批准了别的东西"。
