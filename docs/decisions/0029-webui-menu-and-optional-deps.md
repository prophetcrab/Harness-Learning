# 0029 界面拆分、快捷命令菜单与可选依赖

- 日期：2026-10-14
- 阶段：P3_Coding `_05_Compaction`（收尾补做）
- 状态：已采纳

## 背景

`_05` 收尾时用户问了一句："关于 webui，你觉得有必要把 webui 也拆一下吗？"
考察下来发现两件事，第二件是真 bug：

1. **页面在一个文件里**：`webui/index.html` 1182 行（CSS 307 + HTML 175 + JS 700）。
   改一处要跟"字符串不唯一"较劲；**JS 没法单独做语法检查**——内联在 HTML 里，
   `node --check` 查不了，而测试只断言子串，一个括号写错整页白屏也能过测试。
   两个仪表面板（📐 上下文 / 📊 Token）还各写了一遍"解析地址 → 发现 endpoint →
   iframe 打开 → 轮询徽标"，136 行几乎逐字重复。

2. **界面依赖写成了 `inject = ("agent", "sessions")`**，而 `agent` 依赖 `llm`。
   实测：卸载 `llm` 后 `webui` 从 active 列表消失、端口不再监听；重装 `llm`
   虽然插件回来了，但**端口换了一个**，旧标签页再也连不上。
   也就是说——**模型用自扩展工具装卸 `llm`（或换模型）时，你眼前的界面会失联。**

## 决策

**1) 页面拆成三件套，后端加静态资源白名单路由。**

`index.html`（骨架）+ `app.css` + `app.js`；`STATIC_FILES = {文件名: Content-Type}`
是一个**常量白名单**，而不是"按请求路径读文件"。任何形式的路径拼接都可能被
`../` 走出目录；白名单里的名字请求给不出新的，这条攻击面直接不存在。
（测试覆盖 6 种穿越写法，全部 404。）

同时把两个面板的重复逻辑抽成 `mountPanel(config)`：地址解析顺序、endpoint 发现、
iframe 打开、徽标轮询全在一处，两处调用各给一份配置（徽标文本/提示是回调）。

**2) 快捷命令菜单：没有专属按钮，敲 `/` 提示所有命令（后补，用户要求）。**

`/compact` 最初做成输入框左侧的专属按钮。用户要求改成「输入 `/` 时主动提示
所有快捷命令（`/compact`、将来的 `/goal` 之类）」——采纳，理由不只是省地方：

- **命令变成声明**：`COMMANDS` 表里一行 = 名字 + 说明 + 执行函数；提示、
  前缀过滤、↑↓ 选择、Tab 补全、Enter 执行全部自动。**加第二个命令只加一行**。
- **避免控件堆积**：每个命令摆一个按钮的话，输入框旁边会长出一排各管一摊的
  控件，每个还要单独处理忙态禁用。
- **可发现性**：按钮只告诉你有这一个功能；敲 `/` 一次看到全部可用命令。

键盘契约：`/` 弹出；继续打字即前缀过滤（**含空格就收起**，认作普通消息）；
↑↓ 移动高亮；Tab 补全到输入框（还能改）；Enter 执行；Esc 收起；也可点选
（用 `mousedown` 抢在输入框 `blur` 之前）。

**3) 内核加 `optional` 声明，界面依赖改用它。**

| | 缺依赖时 | 依赖来了 | 依赖走了 | 取值 |
|---|---|---|---|---|
| `inject` | pending，不激活 | 自动激活 | 自动停用 | `ctx.require` 一定成功 |
| `optional` | **照常激活** | **不重装** | **不停用** | `ctx.get` 可能拿到 None |

- **为什么不直接删掉依赖声明**：那只是把问题藏起来——`setup` 里仍然要取服务，
  取不到就炸在打开页面的时候。声明成 optional 有明确语义，且台账里看得见。
- **为什么不重装**：`optional` 里的服务来来去去不该重启一个正在对外服务的插件
  （重启 = 端口换掉 = 用户眼前的页面失联）。这是本决策的核心取舍。
- **代价**：必须**现取服务**。`plugins/webui.py` 里 `agent` / `sessions` 一律
  `ctx.get` 现拿，拿不到就给 503 + 人话（"agent 服务未就绪"），而不是在 `setup`
  里抓一份存着——抓存的那份会指向已停用的旧服务。
- **一致性校验**：同一个服务既必需又可选 → 装载期直接报错（声明矛盾 fail loud）。

**4) 台账暴露可选依赖状态，界面标"降级"。**

`PluginInfo` 加 `optional` / `missing_optionals`；左栏插件名旁出现黄标"降级"，
title 里写明缺哪几样。**降级不是隐藏**——用户看得到"现在是残的"，才不会
对着一个用不了的按钮怀疑人生。

## 备选与排除

1. **引入构建工具（Vite/esbuild）把前端打包**。排除：本项目全程零依赖，
   为了拆文件引整套构建链不划算；原生 ES 模块 + 静态白名单足够。
2. **用 `<script type="module">` 拆多个 JS 模块**。排除：当前只有一个入口文件，
   拆模块解决的是"多入口/循环依赖"，这里没有；等真需要时再上。
3. **给 webui 加一层"稳定门面"（像 RPC 那样另起一个进程）**。排除：过重；
   `optional` 已经把问题解决在正确的一层（生命周期声明），而不是加中间层绕开。
4. **把两个仪表插件合并成一个"管理面板"插件**。排除："插件自带页面、卸载即
   消失"是个特性，不该为去重牺牲；共享的是 `mountPanel` 这段前端代码，不是插件本身。

## 后果

- **收益**：换模型/装卸插件时界面不再失联（端口稳定、标签页不用刷新）；
  前端能单独做语法检查；重复的 136 行面板逻辑归一；新增面板从"抄一遍 70 行"
  变成"写十几行配置"。
- **实测**（真实 DeepSeek，`_05` 服务）：
  - 三件套各自 200 且 Content-Type 正确；CSS 真的生效（计算样式
    `background: rgb(11,13,17)`、三栏 `266px 762px 372px`）；JS 无错误、
    徽标被 `mountPanel` 填上（`📐 上下文 0.2%` / `📊 Token 2,264`）；
  - 换 fs 后 `webui` 仍在 active、端口不变、turn 照跑（回归用例）。
- **约束与已知边界**：
  1. 界面依赖是可选的 → "忘了装 sessions"不在装载期报错，而是打开页面才见 503
     （刻意取舍；`boot.py` 的组合里两者总是一起出现，实际影响为零）；
  2. 静态白名单要手工维护（新增图片/字体得加一行）——"绝不路径拼接"的小代价；
  3. 顺手修的一处显示问题：1M 窗口下百分比恒为 0.x%，取整后永远显示 `0%`；
     现改为**小于 10% 保留 1 位小数**（`0.2%`），够大才取整。
- **债务与后续**：`_11` 收官时若前端继续长大，再考虑模块化拆分；
  目前 774 行单文件尚在一眼看得完的范围内。
