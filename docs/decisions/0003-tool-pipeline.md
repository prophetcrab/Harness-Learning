# 0003 工具执行管线：三段式中间件链，审批 fail-closed

- 日期：2026-10-07
- 练习：P1_Coding/_03_Tool_Pipeline
- 状态：已采纳

> 注：学习计划 M2 章节里写的"决策记录 0002-tool-pipeline"是早期占位编号；
> 0002 已被 `_02` 的 turn/step 记录占用（编号全项目递增、不复用），故本记录为 0003。

## 背景

_01 的 `Toolbox` 只有"注册 + 查表 + 错误包装"，工具执行是一个 `try: func(**args)`
就完事。当工具从"一个计算器"长成"读写文件、跑命令"之后，执行一个工具前后要做的事
突然变多：

- 危险工具执行前要**问人**（审批），且应答方可能不存在（非交互环境）；
- 参数可能需要**校验/改写**（补默认值、规范化路径）；
- 执行可能**卡住**，需要超时；
- 结果可能**过长**，需要截断才能进上下文；
- 某类工具在特定会话里要**禁用**。

如果把这些写成主循环里的一串 `if`，会立刻出现三个问题：循环被安全细节污染、
每个关注点无法单独测试、无法按会话定制。学习计划 M2 明确要求"用中间件链实现
pre/execute/post"，dsh 也是这么做的（`docs/tool-execution-pipeline.md`）。

## 决策

把工具执行拆成三段式管线，每段是一串可插拔中间件，并配一个策略化的审批层：

- **注册表**（`registry.py`）：`ToolDefinition`（定义）与实现函数分离；全局层 +
  `scoped()` 作用域层，解析时 most-specific-wins，作用域同名遮蔽全局但不删全局定义。
- **管线**（`pipeline.py`）：
  - `pre`：按序跑中间件，产出 `allow / deny / ask` 并**短路**；支持中间件**改写参数**
    （改写沿链传递）。无中间件结论且工具 `needs_approval` 时自动转 ask。
  - `execute`：线程 `join(timeout)` 执行；超时返回 `status="timeout"` +
    `code="TOOL_TIMEOUT"`；异常包装成结构化错误。**失败不是异常，是 `ToolResult`。**
  - `post`：按序跑中间件，可返回替换结果（截断、脱敏、附加上下文）。
- **审批**（`approval.py`）：`ApprovalPolicy` 协议 + `AutoApprove / AutoDeny /
  ScriptedApprover / PromptApprover`；**无策略或非交互终端一律 fail-closed 拒绝**。

`ToolPipeline.execute(name, args) -> dict` 实现对 `AgentLoop` 的执行器契约，
因此管线原样插进主循环，`agent_loop` 无需任何改动。

## 备选与排除理由

1. **把审批/超时/截断写进主循环的 if 链**。排除：这正是要消除的耦合；安全策略与
   循环生命周期的变更会互相牵连，且每一段都无法独立测试（"拒绝后没执行"要跑整个循环）。
2. **用装饰器堆叠代替中间件链**（`@timeout @approve def tool(...)`）。排除：装饰器在
   **定义时**固定顺序与策略，无法按会话动态增删（如"本会话禁用某工具"）；中间件是
   运行时可组合的数据，更贴合"注册都是 effect、可叠加可撤销"的方向。
3. **审批默认放行、只在显式配置时拦截**。排除：默认放行意味着配置疏漏 = 危险操作直接
   执行。安全默认值必须是拒绝（fail-closed）——这是 P0 `_04` 已经验证过的教训。
4. **用进程实现超时**（`multiprocessing` 强杀）。排除：引入 IPC、序列化、跨平台开销，
   对一个"演示管线"过重；线程 join 足够表达"超时是结构化结果"，强杀能力留给 M5 的
   `SubprocessService`（那时对象本就是子进程）。
5. **注册表一步到位做多级继承**。排除：M2 只需要证明"分层 + 遮蔽"这一条不变量的
   机制；两级（全局 + 单作用域）已足够，多级留到 M6 的 profile 组装再展开。

## 后果

- 约束：`pipeline.py` 不直接 `input()`、不 import 具体工具；审批只经 `ApprovalPolicy`；
  工具失败一律转 `ToolResult` 而非抛异常。
- 收益：19 个测试 0.19 秒全离线；pre 拒绝可断言"执行器 0 次调用"；审批三态、
  超时、截断、参数改写、作用域遮蔽各自独立可测；管线插入 `AgentLoop` 零改动。
- 债务：超时后工具线程仍在后台（线程无法强杀）；中间件同步串行，无优先级与取消传播；
  注册表仅两层。
- 后续：`_04_Session_Log` 把 `ToolResult` 也纳入事件日志；M5 用真正的
  Provider 接缝（FileSystem / SubprocessService）替换 `builtin.py` 里的直连实现。
