# 0037 管理弹层由自述驱动：壳内置一页只读，插件声明即可顶替

- 日期：2026-10-16
- 阶段：P3_Coding `_06_Tool_Plugins`
- 状态：已采纳

## 背景

`_05` 收尾把"插件台账"做成了一个**独立弹出面板**（用户要求："应该是一个单独的
点击可弹出界面来进行管理，你要做的尽可能的美观"）。但那一页是**壳里写死的**：

- `index.html` 里有 `#ledger-entry` 门卡、`#plugin-modal` 骨架、`#pm-*` 一整套元素；
- `app.js` 里写死了取数地址（`/api/plugins`）、快照字段名（`groups/installable/actions`）、
  卡片画法，以及 `/api/plugins/<name>/<action>` 的动作地址约定。

`_06` 要让"工具管理"也进同一个面板。按当时的写法，只有两条路：再写一页
（**第三次改壳**），或者把两个管理面硬合成一页。两条都不好——"界面零知识"
（决策 0032）在展示层是假的：**加一个管理面就得改壳**。

## 决定

补第四条界面自述 `AdminSpec`（`components/shell/admin.py`），与 panels / display /
routes 同构：

    插件声明：key / label / title / summary / snapshot 地址 / action 地址模板 / foot
    壳只做：画标签页 → GET 快照 → 按**通用形状**画卡片 → POST 动作（占位替换）

通用快照形状**沿用 `_05` 的插件快照**（groups[].plugins[] + installable + actions）：
一份渲染器同时服务插件页与工具页。字段名沿用而非另起一套——分叉就会静默少画
一块，而这个项目已经因为"两份相似的声明各写一份"吃过亏（决策 0031）。

**降级规则（replace-by-key）**：壳内置一页**只读**的「插件」（key=`plugins`），
直接读 `/api/ledger` 的内核台账，不依赖任何插件；插件声明了同 key 的一页就
**顶替**它。于是：

    装了 plugin-admin   → 它的页（带按钮）在
    没装 plugin-admin   → 内置只读页（能看，不能操作），不是空白也不是报错

## 为什么

**理由一：这是"壳零知识"在展示层的最后一块。**
后端早就做到了（服务自己暴露地址、插件自述面板/显示/路由）；但管理面还是
壳写死的。补上这条之后，`app.js` 里不再出现任何具体管理面的地址
（测试钉住：`api/plugins` / `api/tools` 不许出现在 app.js 里）。

**理由二：内置只读页让"管理插件被自己关掉"有一个体面的结果。**
管理插件是能力插件（允许停用/卸载，见决策 0033）。它一走，管理能力就没了——
但"看"不应该跟着没。内置页只读地展示内核台账：用户仍能看到当前有哪些插件、
什么状态，只是没有按钮。

**理由三：动作地址用模板，壳不猜命名约定。**
`action = "api/tools/{name}/{action}"`——壳只做两次字符串替换（含 URL 编码）。
猜约定（如"总是 /api/<key>/<name>/<action>"）等于壳又认识了插件。

## 代价（如实记下）

- **一页的字段约定仍然存在**（groups/plugins/actions/tags/note）：它不是类型，
  是"渲染器与快照之间的口头约定"。缓解：两边（渲染器与两个管理面）都在同一个
  阶段里写，且 UI 测试真跑渲染逻辑；但**新写一个管理面时仍要照这个形状来**，
  写岔了会静默少画——这是这份决定没有完全消灭的那点耦合；
- **壳内置了"只读插件页"**：严格说壳里出现了"插件"这个概念（内置页的 key、
  分组标签）。取舍是：没有它，管理插件缺席时界面就是空白。**它只读内核台账**，
  不涉及任何具体插件的知识。

## 备选方案与否决理由

**A. 每个管理面各写一页。**
第三次改壳，且以后每加一个管理面都改——"完全插件化"的承诺在展示层失效。

**B. 把工具管理并进插件管理页（一个页面两个区块）。**
两者策略不同、生命周期不同：插件管理是**装配级**策略（base 不可卸），
工具管理关心的是工具面（owner / 按工具开关）。合并后"关掉一件工具"会牵扯到
应用台账的操作入口。而且 `tools` 插件卸载后，工具管理这一半应当整体消失——
分页天然做到，合页做不到。

**C. 让插件自己提供一段 HTML 模板（壳只做插值）。**
等于让插件写壳的渲染代码：样式与交互会各写各的，且插件侧要理解壳的 DOM 约定
（比现在的形状约定更重的耦合），还会把 XSS 面打开。四种通用渲染器
（决策 0032 的 display）与这套形状的思想一致：**壳提供固定的几种，插件在里面选**。
