# 0031 插件声明纪律：把"约定"变成"不变量"（三处耦合修复）

- 日期：2026-10-15
- 阶段：P3_Coding `_05_Compaction`（收尾补齐；用户要求"不要过于耦合"）
- 状态：已采纳

## 背景

用户问了一句："现在的代码架构符合我们对于完全是插件的原预期吗？"

逐项实测后发现：**三层分离是对的**（`kernel/` 不认业务、`components/` 不 import
kernel、插件之间零直接 import、协作全走 ctx），**`inject` 生命周期也是真的管用**
（换掉 `tools` 插件，声明了 `inject` 的 `self_tools` / `clock` 会被自动重启，
注册的工具都还在）。

**但"完全插件化"还差三处**——都是"约定靠人记、没人检查"造成的：

1. **声明会漏，漏了不响**：`token-usage` 用 `ctx.get(TOOLS_SERVICE)` 注册工具
   却没声明这个依赖。换掉 tools 插件时内核不知道要重启它，`usage_stats`
   **从工具面上永久消失**（实测确认）。
2. **前端壳认识具体插件**：后端做到了"界面不认识插件"（`endpoints` 自报地址），
   但 `app.js` 里**写死了**两个面板（`service: "context-meter"` / `"token-usage"`）。
   加第三个面板插件就得改壳——注释里"页面不认识任何插件"是夸大的。
3. **一插件两职责时声明语义不明**：`token-usage` 既是"账本"（状态）又"暴露
   工具"。声明 `inject` → 换容器时整个插件重启、账本历史丢失；声明 `optional`
   → 不重启、工具还是丢。两个都不对。

## 决策

**1) 声明纪律用测试钉住（修复 1）。**

新增 `tests/test_s05_plugin_discipline.py`，用 AST 扫源码找出"取了哪些服务"
（`ctx.get(X)` / `ctx.require(X)`，X 支持字符串与常量名），再和插件类上的
`inject` / `optional` 声明求差集，非空即失败。

- **为什么用 AST 而不是运行期**：等待中的插件不执行 `setup`，跑一遍查不全；
  静态扫描能覆盖到"将来激活时才用到"的代码路径。
- **为什么值得**：这条测试的价值不在"现在绿"，而在**以后每个新插件都躲不过**。
  漏声明会当场变红，而不是等到某个插件被换掉时才发现东西没了。

**跑出来的结果：揪出 6 个插件共 8 处漏声明**（不止 `token-usage`）：
`agent`（approval/compacter）、`rpc`（tools）、`self_tools`（approval/fs）、
`tools`（subprocess）、`web_approval`（fs）、`webui`（approval/tools）。
逐条按**用途**补声明：有 None 兜底的 → `optional`（可选能力）；无兜底、
缺了就坏 → `inject`。

**2) 面板自述：把挂载点从壳里挪回插件（修复 2）。**

`components/panel/spec.py` 定义 `PanelSpec`（服务名 / 按钮文字 / 标题 / 徽标读
哪个 JSON 的哪个字段 / 排序权重），插件在自己那个**服务对象**上挂
`panels = (...)`,webui 的 `/api/ledger` 收集后交给页面，页面遍历生成按钮。

- 形状定义放**一处**：面板是壳与插件之间的契约，两边必须对同一套字段达成一致；
  散在各插件里各写一个 dict，字段名一漂移（`path` vs `url`）就静默不显示。
- 壳只做三件通用的事：放按钮、点开显示那个插件的页面、按声明读个数字贴上去。
  **业务呈现留给插件自己的页面**——那才是它该负责的地方。
- 结果：`index.html` 里两个写死元素换成通用容器，`app.js` 里两处 `mountPanel`
  调用换成一次遍历。**加面板插件不用改壳**（用测试钉住：壳里不许出现任何
  具体插件名）。

**3) 账本挂实例，声明 inject（修复 3）。**

`token-usage` 改为 `inject = (TOOLS_SERVICE,)`（与 self_tools / clock 同一约定：
**注册工具的插件都声明这个依赖**），同时把账本与"当前会话"从 `setup` 局部
提升到**实例**上。

关键区分是这一条：

> **插件的"激活状态"（登记了什么、起了什么服务）会被回卷，
> 但插件的"身份与它自己积累的数据"不该被回卷。**

内核的本事就是"停用只回卷 effect，不丢插件对象"——`_deactivate` 把状态退回
`pending`，重新激活时 `setup` 在**同一个实例**上再跑一遍。账本放实例上，
历史就不会因为"容器换了个插件"而被清空；真正的 `unload_plugin` 才丢弃实例，
那时账本归零是对的（与"卸载即回卷"一致）。

实测：换掉 tools 插件后 `usage_stats` 仍在工具面，账本 `calls=2 / 330 tokens`
的历史**原样保住**；而修复前工具直接消失。

## 备选与排除

1. **靠注释/文档提醒"记得声明"**。排除：靠人记的约定一定会漏，而且漏了不响
   （这次就是）。
2. **运行期检测（跑一遍所有插件的 setup 再比对）**。排除：等待激活的插件不执行
   setup；还会因为副作用把测试环境搅乱。
3. **面板继续在壳里列举**。排除：那就等于"加面板要改壳"，"完全插件化"在界面上
   是假的。
4. **把 token-usage 拆成"账本插件 + 工具插件"两个**。排除：为了声明语义多切一个
   插件，代价大于收益；实例态方案已同时满足"能重启"与"不丢历史"。
5. **面板自述用 Protocol 而不是 dataclass**。排除：这里描述的是**数据**
   （要序列化进 JSON 交给浏览器），不是行为。

## 后果

- **收益**：声明不再靠自觉（测试看守）；界面上"加面板插件不用改壳"是真的；
  换插件不再静默丢东西（工具/历史都保住）。
- **实测（浏览器）**：面板按钮由自述生成（`📐 上下文 0.0%` / `📊 Token 0`），
  点击切换正确（标题与 URL 都对）；审批卡片弹出 → 批准 → 视图正常，徽标刷新为
  `0.2%` / `20,044`。
- **约束与已知边界**：
  1. AST 扫描认不出"把服务名从别处算出来"的写法（`ctx.get(getattr(x, "name"))`）
     ——真出现时测试会漏报，但那属于刻意绕开约定的写法；
  2. 面板契约只支持"点开看插件页面 + 一个数字徽标"；复杂呈现留给插件自己的页面；
  3. "壳零知识"靠测试钉住（壳里不许出现插件名）——比人工 review 可靠。
- **债务与后续**：`components/panel/` 是新增的构件包，若将来出现"非 iframe 形态
  的面板"（如内嵌图表），需要扩展 `PanelSpec`（当前刻意只支持最简单的一种）。
