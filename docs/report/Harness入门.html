02 HARNESS 介绍

Harness 介绍

Agent = Model + Harness

核心思想

模型已经会调用工具、会规划任务。
怎么让它安全、有效、正确地达成目标？

Agent = Model智能 + Harness控制

答案在模型之外：记忆、上下文、边界和能力
由 Harness 这一层统一负责。

01
Agent 运行框架 模型和工具交替推进，直到任务完成。
主循环流式输出取消与超时 并行工具调用步数上限子代理
02
上下文管理 控制模型每一步能看到什么、能看多久。
提示词装配变量插值运行时注入 历史裁剪自动压缩token 预算前缀缓存
03
工具与能力管理 所有对外动作都从这里经过，可校验、可拦截、可替换。
工具注册表schema 校验执行管线 审批沙箱能力接缝 插件 / MCP结构化错误
04
会话与持久化记忆 一切发生过的事都可查、可续、可分叉。
事件日志历史投影崩溃修复 resumeforkfollow 长期记忆审计导出
模型负责智能，Harness 负责让智能可靠地落地。 ← 返回封面 Esc 关闭弹窗

02 HARNESS 介绍 · 3 / 3

一个常被忽略的优化

前缀缓存：同样的开头，第二次就便宜了

多轮对话里，前缀其实一直在被复用

PREFIX / NEW / REBUILD

每轮只在末尾追加新消息；从第 2 轮起，前面那段已经算过，可以按缓存价复用。

第 1 轮
system user 1
第 2 轮
system user 1 reply 1 user 2
第 3 轮
system user 1 reply 1 user 2 reply 2 user 3
第 4 轮
system user 1 reply 1 user 2 reply 2 user 3 reply 3 user 4
第 5 轮
system user 2 reply 2 user 3 reply 3 user 4 reply 4 user 5

第 5 轮：窗口满了，从头部裁掉 user 1 / reply 1。 前缀在 system 之后就断了：只有 1 条仍命中缓存， 中间 6 条原本能命中，现在必须重算，末尾 1 条照常新增。

前缀命中缓存，按缓存价计费 本轮新增，必须重新计算 前缀已断，原本能命中也要重算

WHY IT MATTERS

模型收到输入后，会先做 prefill——把整段上下文过一遍，为每个 token 算出注意力需要的 Key/Value 向量。这一步的计算量随上下文长度增长，长上下文下还会按平方涨。

厂商把这段 KV 结果按前缀内容缓存下来。多轮对话里，只要开头没变，前面那段的 KV 可以直接取用、不用重算，于是省下大笔 prefill 开销，也明显降低了首字延迟。

当组件被完全移除时，它造成的副作用能够被完全撤回， 系统运行态完全恢复到组件安装前的状态。

组件之间的依赖可以被声明，由运行时响应式地管理—— 依赖自动就位，无需手动编排激活与退位的顺序。
