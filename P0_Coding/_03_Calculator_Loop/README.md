# _03_Calculator_Loop —— 模型 → 工具调用 → 模型的循环演示

P0 第三个练习：换一个**完全离线**的计算器工具，把"模型 ⇄ 工具"的循环本身演示清楚。

## 学习目标

1. 看清循环的形状：**每一轮 = 一次模型调用**；模型申请工具 → 本地执行 → 结果回填 → 再调模型，直到模型不再申请工具。
2. 观察两个事实（运行日志里直接可见）：
   - **申请与执行分离**：模型只说"请调 `calculate({"expression": "1234*56.78"})`"，真正运算的是脚本里的 Python 代码；
   - **模型无状态**：每轮打印"发出 N 条消息"，历史逐轮变长（2 → 5 条）。
3. 学一个安全要点：**绝不 `eval()` 模型生成的字符串**——本脚本用 `ast` 白名单求值，
   函数调用（`__import__('os')`）等语法会被直接拒绝。

## 一次真实运行（节选）

```
[模型第 1 次调用] 发出 2 条消息 + 1 个工具说明书
  → 返回：申请调用 2 个工具（注意：只是申请，还没执行）   ← 模型一轮里并行申请两个计算
[执行第 1 次] calculate({"expression": "1234*56.78"})
                 → 结果：70066.52
[执行第 2 次] calculate({"expression": "1234*56.78*0.85"})
                 → 结果：59556.542
  → 结果已回填，继续下一轮

[模型第 2 次调用] 发出 5 条消息 + 1 个工具说明书
  → 返回：最终回答（finish_reason='stop'，没有申请工具）

════════ 最终回答 ════════
- 原价总额：1234 × 56.78 = 70066.52 元
- 折后总额（8.5 折）：59556.542 元（约 59556.54 元）

════════ 本次运行统计 ════════
模型调用：2 次
工具执行：2 次
token 合计：prompt=1025  completion=200
```

## 验收标准

- [x] `--calc-only "1234*56.78"` → `70066.52`（精确计算）
- [x] `--calc-only "1/0"` → 结构化错误 `division by zero`（不崩溃，错误回给模型）
- [x] `--calc-only "__import__('os').system('dir')"` → 拒绝：`不支持的语法：Call`（安全）
- [x] `--calc-only "9**9**9"` → 拒绝：`指数超出上限 100`（防资源滥用）
- [x] 完整循环真实跑通：模型自主申请 2 次计算并基于结果作答
- [x] `--no-tools` 对照跑通：无工具时只调 1 次模型、无工具执行
- [x] `pytest -q` 全部通过（5 个用例）

## 循环的形状（对照 harness 概念）

```
组装 messages（system + user）
       ↓
   ┌─ 调模型 ────────────────────────────────┐
   │   返回 tool_calls？                      │
   │     ├─ 是 → 把申请存回 messages           │
   │     │      逐个执行工具 → 结果回填        │
   │     │      → 回到"调模型"（下一轮）        │
   │     └─ 否 → 最终回答，循环结束            │
   └──────────────────────────────────────────┘
```

- 这个"一次模型调用 + 它引发的工具调用"就是 dsh 里的 **step**；
- 循环外面的"一次用户输入到最终回答"是 **turn**；
- `max_rounds=6` 是防止模型停不下来的**步数预算**（dsh 里有更完整的停止策略）；
- 执行失败转结构化错误回填，对应铁律 #7"**错误是给模型的输入**"。

## `--no-tools` 对照实验说明什么

同一个问题不给工具时：模型调用 1 次、工具执行 0 次，全靠心算。这次运行它算对了
（简单算术），但对照的意义在于：

- **无工具**：结果无法验证，复杂计算容易出错，错了你也不知道；
- **有工具**：计算确定性、可追溯，模型只负责"决定算什么"。

这也是 harness 设计的底层理由：把模型不擅长的确定性工作交给工具，让模型专注决策。

## 已知限制（故意的）

- 一次运行一个会话，退出即忘——没有多轮对话记忆（M3 会话日志解决）；
- 工具注册表仍是硬编码字典，没有审批/超时管线（M2 内容）；
- 没有流式输出（模型返回在每轮结束后才打印）。
