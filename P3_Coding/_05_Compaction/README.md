# _05_Compaction —— 上下文压缩（历史不改写，投影里折叠）

P3 第 5 阶段（对应 [PLAN.md](../PLAN.md)）。**本阶段只加一个机制**：

> 超阈值时把**旧区段**摘要成**一条消息**；日志用"折叠声明"实现，绝不改写历史。
> 验收：压缩后投影变化、日志原样、**重放仍然同构**。

**两种触发方式，一套机制**：自动（到 90% 阈值）+ 手动（`/compact`：REPL 命令、
网页里敲 `/` 弹出的命令菜单）。

**状态：✅ 已完成（2026-10-14）**

## 为什么这样设计

四个决定，每个都有明确的代价与理由：

**① 阈值：90% 触发、尾巴留 10%、摘要 ≤5% 容量**（用户定调）。
压完落在 15%~20%，离下一次触发很远——压缩必然打断一次前缀缓存，所以
**次数越少越好**。这是"少压一点、但压得很稀"的取向，与"频繁小压"相反。

**② 日志只追加一条 `compact/checkpoint`，不删不改任何旧事件。**
铁律 #1（模型可见即已记录）与"日志即真相"要求历史只能被**遮蔽/折叠**，
不能被重写。所以 checkpoint 是一句**声明**："写我的时候，对话列表最前面的
`folded` 条已经折成这句摘要了"。投影（`derive_messages`）读到时按**位置**
丢掉那几条、把摘要顶到最前——日志一条不动，重放自然同构。

> 踩坑记录：最初按 **seq** 折叠（"丢掉 seq ≤ X 的"）。但摘要自己带一个
> 更大的 seq 坐在列表最前，列表的 seq 因此不再单调——"折 1 条"实际掉了 3 条，
> 内存历史与日志投影当场失同步。**按位置折叠**与循环内存里的切片
> (`history[start : start+folded]`) 逐条对应，两个视图天然对齐。

**③ 当前 turn 永不折叠**（`protect_from` / `floor` 钳位）。
刚问的问题、刚拿到的工具结果不能在"干活干到一半"时被摘要掉。
代价写在"已知边界"里。

**④ 失败即放弃**（fail-soft）。摘要调用出错/返回空 → 只记一条瞬态
`compact_failed`（不进日志），本轮照常继续。压缩永远不能把对话搞死。

## 怎么用

```bash
cd P3_Coding/_05_Compaction
python -m pytest -q                                # 246 个用例

python chat.py --web --realtime --self-tools        # 默认 1M 窗口
python chat.py --realtime --context-window 8000     # 小窗口：多聊几轮就能看见压缩
                                                    #（触发线 7200、尾巴 800、摘要 400）
```

界面上：聊天流里出现 `⟳ 上下文已压缩：折叠 N 条消息（约 X → Y tokens）`，
点开看模型眼前的摘要全文；事件流里同名事件带 `folded` / `before` / `after`。

**手动触发（`/compact`）** 两种按法，同一个动作：

```
网页：输入框里敲 "/" → 弹出命令菜单 → Enter 执行（Tab 补全，Esc 收起）
终端：REPL 里敲 /compact                      ← chat.py 命令
```

**没有专属按钮**——这是刻意的（见「快捷命令菜单」一节）：命令是一张声明表，
敲 `/` 主动提示全部，加新命令只加一行。

手动与自动的**唯一差别**是"何时压、折到哪"：手动跳过阈值（用户叫了就压），
切点折到**最后一轮之前**（自动按"保留 10% 容量"往回攒——1M 窗口下 10% 是
10 万 token，按预算切等于什么都不折）。**其余守卫一个不少**：最后一轮原样保留、
末尾至少 2 条、不劈开 tool 配对；日志语义与投影折叠也完全一致。
失败时人工路径**不静默**（回一句原因），自动路径才是 fail-soft 悄悄跳过。

## 机制怎么运作

```
每 step：              plan_compaction(内存历史, 工具面, 策略, measured=上次实测)
                          │
              用量 = max(字符估算, 实测 prompt_tokens) ── 不到阈值 → 什么都不做
                          │ 超了
                     choose_cut：从尾部往回攒到"保留预算"
                          ├─ floor 钳位：当前 turn 一条都不折
                          ├─ min_tail：末尾至少 2 条（一次工具往返）
                          └─ 成对安全：切点落在 tool 消息上就左退
                          │
                    一次普通模型调用（无工具、历史摊平成文本）
                          │  失败/空 → compact_failed（瞬态，本轮跳过）
                    折叠：history[start : start+folded] → [一条摘要消息]
                          │
                    emit compact_applied ──► 录制器追加 compact/checkpoint
```

**触发用量的两个来源**：估算（无 tokenizer）与实测（`usage.prompt_tokens`）。
取 `max` 是保守的一侧——实测来自**上一个**请求，本请求只会更大。
`used_source` 如实标注是哪一个（页面上也能看到）。

**摘要请求的内容**：折叠区消息**摊平成文本**（`[user] … [tool] 结果 → …`），
不原样发——因为很多供应商要求"带 tool 消息就必须同时带 tools 声明"，
摊平谁都能读。超长时"第一条 + 从最新往回填"，中间标"已略"（裁剪有损，
但压缩本身有损，写明比假装完整强）。

## 手动触发（`/compact`）的两条防呆

1. **空折守卫**：折叠区若只剩上一次的摘要（连按两次 `/compact` 会走到这里），
   直接返回 None——新摘要 ≈ 旧摘要，白花一次调用还可能越摘越薄（实测踩到）。
2. **"没有可压缩的历史"**：只有当前一轮时同样返回 None，界面回一句
   「没有可压缩的历史（只有当前一轮）」，而不是假装压缩成功。

## 界面重构（`_05` 收尾时补做）

**① 快捷命令菜单（没有专属按钮）**

`/compact` 最初做成了输入框左侧的一个专属按钮。改成"敲 `/` 主动提示所有命令"
之后，命令变成 `COMMANDS` 里的一行声明（名字 + 说明 + 执行函数），
提示 / 前缀过滤 / ↑↓ 选择 / Tab 补全 / Enter 执行全部自动。

好处在**加第二个命令时**才显出来：`/goal` 之类只需往表里加一行——
不用再摆一个按钮，也不会在输入框旁边堆一排各管一摊的控件。
键盘契约：`/` 弹菜单、继续打字即过滤（含空格则收起，认作普通消息）、
↑↓ 移动、Tab 补全、Enter 执行、Esc 收起、点选也行（mousedown 抢在 blur 之前）。

**② 页面拆成三件套**：`index.html`（骨架）+ `app.css` + `app.js`，由后端加两条静态路由提供（白名单，不做路径拼接——见 `STATIC_FILES`）。

收益有三条：1182 行的单文件变成各司其职的三份；**JS 能单独做语法检查**（`node --check app.js`——以前内联在 HTML 里查不了，一个括号写错整页白屏，而测试只断言子串照样绿）；改一处不再有"字符串不唯一、Edit 失败"的麻烦。

顺带去掉一份重复：两个仪表面板（上下文 / Token）原本各写一遍"解析地址 → 发现 endpoint → iframe 打开 → 轮询徽标"，136 行几乎逐字重复；现在抽成 `mountPanel(config)` 一个工厂，两处各给一份配置。

**③ 界面依赖从 `inject` 改成 `optional`——修掉一个真 bug。**

原声明 `inject = ("agent", "sessions")` 看着自然，但 `agent` 依赖 `llm`：**模型一用自扩展工具装卸 `llm`（或换模型），整条依赖链连锁停用，界面服务当场停掉、端口关闭、你眼前的页面失联。** 实测：卸载 llm 后 `webui` 从 active 列表消失、端口不再监听；重装 llm 虽然插件回来了，但端口已经换了一个，旧标签页再也连不上。

修法是在内核加 `optional` 声明（`kernel/plugin.py` 有完整语义表）：

| | 缺依赖时 | 依赖来了 | 依赖走了 | 取值 |
|---|---|---|---|---|
| `inject` | pending，不激活 | 自动激活 | 自动停用 | `ctx.require` 一定成功 |
| `optional` | **照常激活** | **不重装** | **不停用** | `ctx.get` 可能拿到 None |

`optional` 的取舍很清楚：换来"永不因别人来去而被重启"（端口稳定、页面不掉线），代价是必须**现取服务**——`plugins/webui.py` 里 `agent` / `sessions` 一律 `ctx.get` 现拿，拿不到就给 503 + 人话（"agent 服务未就绪"），而不是在 setup 里抓一份存着（那会指向已停用的旧服务）。台账里也会标出"降级"（左栏插件名旁的黄标）。

## 收尾：三处耦合修复（用户要求"不要过于耦合"）

做完压缩后回头审视"完全插件化"到底做没做到位，实测查出三处**约定靠人记、
没人检查**的耦合缺口：

**① 声明会漏，漏了不响。**
`token-usage` 用 `ctx.get(TOOLS_SERVICE)` 注册工具却没声明这个依赖——换掉
tools 插件时内核不知道要重启它，`usage_stats` **从工具面上永久消失**。
修法：新增 `tests/test_s05_plugin_discipline.py`，**用 AST 扫源码**找出每个插件
"取了哪些服务"，与 `inject`/`optional` 声明比对，漏了即失败。
这条测试当场揪出 **6 个插件共 8 处**漏声明，逐条按用途补上（有 None 兜底的
→ `optional`；缺了就坏的 → `inject`）。

**② 前端壳认识具体插件。**
后端做到了"界面不认识插件"（`endpoints` 自报地址），但 `app.js` 里写死了两个
面板（`service: "context-meter"` / `"token-usage"`）——加第三个面板插件要改壳。
修法：`components/shell/panel.py` 定义 `PanelSpec`，插件在自己那个服务对象上
声明 `panels = (...)`,壳**遍历**这个列表生成按钮。加面板插件不用改壳（用测试
钉住：壳里不许出现任何具体插件名）。

**③ 一插件两职责时声明语义不明。**
`token-usage` 既是账本（状态）又暴露工具：声明 `inject` → 换容器时整个插件
重启、账本历史丢失；声明 `optional` → 不重启、工具还是丢。
修法：声明 `inject`（与 self_tools / clock 同一约定：注册工具的插件都声明它），
同时把**账本挂到实例上**。关键区分：

> **插件的"激活状态"会被回卷，但"身份与它自己积累的数据"不该被回卷。**

内核停用插件只回卷 effect、不丢实例，所以重新激活时 `setup` 在同一个实例上
再跑一遍——账本因此保住。实测：换掉 tools 后工具仍在、`calls=2 / 330 tokens`
历史原样。

**实测（浏览器）**：面板按钮由自述生成（`上下文 0.0%` / `Token 0`），
点击切换正确；审批卡片弹出 → 批准 → 徽标刷新为 `0.2%` / `20,044`。

## 收尾之二：壳的两条扩展点（界面零知识）

第一批耦合修复解决了"面板"，但**"事件怎么画"与"插件专属端点"仍写死在壳里**：
`app.js` 里是 `case "compact_applied"`、`webui.py` 里是
`POST /api/sessions/<id>/compact`——加一个需要端点或特殊渲染的插件还得改壳。

现在 `components/shell/` 统管三类自述，壳只按声明分派：

| 自述 | 回答什么 | 壳怎么做 |
|---|---|---|
| `PanelSpec` | 我有个页面 | 给我一个顶栏按钮 |
| `DisplaySpec` | 我的事件该怎么画 | 按四种**通用渲染器**之一画 |
| `RouteSpec` | 我有专属端点 | 挂载 + 负责传输 |

- **四种渲染器**：`fold` 可折叠徽标 / `note` 一行小字 / `warn` 黄条 /
  `status` 只更新状态栏。固定四种——壳不该长成模板引擎，特殊呈现归插件自己的页面。
- **路由 handler 完全不碰 HTTP**：拿解析好的参数与 JSON 体，往 `stream()` 写帧。
  分块传输、CRLF 分帧、终止块全归壳（那几处最容易写错，实测踩过三次）。
- **收尾帧由插件标注**（`terminal: true`），前端合并壳内置的 `__done`/`__error`
  与插件自述——不再写死 `__compact_done` 这种插件专属名字。
- **审批卡片保留专门处理**：它是**交互**（要按钮、要回传）不是**展示**——
  display 的职责边界就到"把一条事实画出来"为止。

**效果**：`webui.py` 里 compact/approval 的提及 10 处 → **0 处**；
`app.js` 17 处 → 5 处（全是审批交互与 CSS 类名），**业务事件名与帧名归零**。

实测（浏览器，真实 API）：`/compact` 走插件自述的路由 → 折叠徽标按 `fold`
渲染器画出 → 收尾帧按 `status` 渲染器更新状态栏。

## 收尾之三：插件管理（分类 + 一键开关）

`list_plugins` 只回答了"有什么"，没回答"**哪些能删**"。`llm` 卸了应用就不成立，
`clock` 随时可以加——这个区别此前只存在于人的脑子里。另外想临时关掉用量统计，
只能 `unload_plugin`（从账本消失，要回来得走 `install` 的人工审批）——
**为了"暂时不要"而走"引入代码"的审批流程，说不通。**

三件事：

**① 分类是插件的声明。** 内核新增 `category`（`base` / `capability` / `other`，
缺省 `other`），只负责读出来、记进台账，**不解释含义**——"base 不可卸载"是
产品策略，归 `plugins/plugin_admin.py`。未声明取 `other` 是保守取向：漏声明的
后果是"一个地基插件看起来可卸载"（人一眼能发现），而不是反过来。

**② 内核同时提供 `disable` 与 `unload`。** disable = 回卷 effect 但**注册留在
账本里**，同一个实例上 `enable` 原地复活；unload = 从账本移除。有个隐蔽的坑：
状态必须**先设、后回卷**，否则回卷过程中触发的 `settle` 看到它还是 `pending`、
依赖也齐，**当场重新激活**——`enable` 时撞 `DuplicateSlotError`。

**③ 白名单只有一份。** 模型侧（`install_plugin` 工具）与界面侧（"可安装"列表）
共用 `plugins/catalog.py`——两份必然漂移。测试按内容断言而非对象身份
（阶段目录各持同名包、conftest 会驱逐 `sys.modules`，`isinstance` 会诡异失败）。

界面：**独立的插件台账面板**（用户要求"做成一个点开的管理界面，尽可能美观"），
左栏只留一张"门卡"显示 `14/14 活跃 · 管理 · 可装 2 ›`。

面板里按分类分三组铺**卡片网格**（自适应列数），每张卡片说清"我是谁、什么状态、
依赖什么、能做什么"：

- **状态**用颜色区分（运行中绿 / 等待依赖紫 / 已停用黄 / 失败红），左侧竖条按分类着色；
- **依赖**用代码体标出（`fs` / `subprocess`），可选依赖标"降级运行"；
- **按钮由服务下发**（见下表），壳只负责画出来、POST、把返回的话显示成面板里的回执；
- **筛选框**按名字或依赖过滤，整组没命中就把组头一起收起；
- 可安装的插件是**虚线"空位"卡片**，一眼看出还能装什么。

为什么是弹出层而不是侧栏：台账要频繁操作（开关插件），挤在 266px 的左栏里
每个插件只剩一行、按钮小到难点；独立成层后一屏能看全 16 张卡片。

> 踩坑：面板每 2.5 秒随 `loadLedger` 刷新一次，最初无脑重写 `innerHTML`，
> 结果卡片反复播入场动画、滚动位置被顶回顶部。改成**内容变了才重画**
> （快照 JSON 做戳）并保留滚动位置。

| 分类 | 状态 | 按钮 |
|---|---|---|
| base | active | （无）卡片标"不可卸载" |
| base | 非 active | （无）"基础插件：依赖未就绪，等它自己激活" |
| capability / other | active | 停用 · 卸载 |
| capability / other | disabled / failed | 启用 · 卸载 |
| capability / other | pending | 卸载（附"等待依赖：…"） |

改策略不用碰 `app.js`——0032 那两条扩展点的首次真实使用。

**实测（浏览器）**：面板开合（含点遮罩、Esc、关闭按钮三条路径，关掉会清空筛选）、
筛选（输入 `tool` → 5 张卡片命中、空组收起）、**安装 clock**（面板里直接长出新分组，
回执"已安装 clock"）、**卸载 clock**（回执"已卸载 clock"，分组消失、回到"可安装"）、
以及此前的停用/启用。刷新不再打断阅读（节点不重画、滚动不动）。

## 收尾之四：turn 执行器（并行会话 / 刷新不掉 / 可中断）

用户问"多个会话能并行吗"，答案是不能——**三层串行**叠在一起：agent 服务一把全局
锁包住整个 turn、webui 入口又一把锁。于是 A 会话跑 30 秒，B 会话就得在门口等。
用户接着提了三条：并行；刷新页面维持运行且**可视化**；运行中发消息**先问要不要中断**。

新建 `components/agent/runner.py`：**turn 跑在后台线程里，HTTP 请求只是订阅者**。

| 端点 | 作用 |
|---|---|
| `POST /api/sessions/<id>/send` | reserve（忙就 409）→ 发响应头 → 挂订阅者 → 起线程 |
| `GET  /api/sessions/<id>/turn` | 只订阅（**刷新后接回**正在跑的那个） |
| `POST /api/sessions/<id>/interrupt` | 请求中断（协作式） |

四件必须做对的事：

1. **顺序**：`reserve`（忙就 409，此时还没发头）→ 发 200+chunked → 挂订阅者 →
   `launch`。倒过来的话快 turn 会在订阅者挂上之前把帧发完，客户端一帧都收不到
   （现有的流式回归测试当场抓到了这个竞态）。
2. **锁粒度**：`AgentService.ask` 只持**这条会话自己的锁**（同会话串行、跨会话并行），
   全局锁退化成只护几个 dict 的短临界区。观察者新增 `watch()`（追加订阅，返回退订
   函数）——刷新时新旧连接并存，`open(on_event=)` 的替换语义会把先来的顶掉。
3. **推流通道按线程登记**：审批原先靠一个全局 sender 槽，并行后 A 等审批时 B 会
   覆盖它。改 ContextVar **实测失败**——阶段目录各持一份同名包、conftest 驱逐
   `sys.modules`，模块级全局在两份副本里不是同一个对象（`isinstance` 栽过三次的
   同一个坑）。最终改成挂在服务对象上按线程 id 登记。
4. **中断不粘性**（真 bug）：`cancel()` 原注释写着"之后所有 turn 都取消"。在
   "中断后重发"的用法下，重发那条会在 **0 步**处被立刻取消——看上去像"会话坏了"。
   同时给非流式 provider 调用补了一刀取消检查（原先只在 step 边界查）。

界面：会话列表带脉冲绿点 + "运行中"；运行中发消息**不静默吞掉也不排队**，弹选择条
（`中断并重新发送` / `等它跑完（接着看）` / `取消`）。重发要处理两件事：中断可能
**扑空**（turn 刚好跑完，不是失败，照样重发）；取消是协作式的（在跑的工具要返回），
这期间服务端仍回 409，所以带 `retryBusy` 轮询等它让开。

**顺带修掉**：被放弃的流会污染后续请求——流式响应原先与普通请求共用 keep-alive
连接，客户端中止后残留帧让下一次复用连接的请求解析歪（实测 `GET /api/sessions`
收到 **501**，界面表现是"重发无声无息地没发生"）。现在流式响应一律
`Connection: close`。

**实测（最终代码，HTTP + 浏览器）**：并行——两条会话重叠 1.5s（串行需约 3.1s）；
刷新——掐断连接后 `running=true`，`GET /turn` 接回 454 帧直到 `__done`；
中断——终帧 `cancelled`；**中断后重发完整闭环**——turn 1 `cancelled`、turn 2 `done`
（6 步）；运行中再发 → 409 + 界面弹选择条。

**全面测试（用户要求"做一次全面测试看看有没有 bug"）又挖出三处**，都有回归测试
且反向验证过（去掉修复即失败）：

1. **`load()` 的写回截断吃掉并发 append**（数据丢失）：`load` 不是纯读——发现崩溃
   残尾时会写回截断。改造后 turn 在后台线程持续 append、界面每 5 秒轮询 load，
   于是"读到快照 → 期间追加 → 按旧快照截断"这个窗口被反复敲。修法：`append` 与
   `load` 共用一把锁，罩住"读 → 判定 → 写回"整段。
2. **排队的第二个 turn 收到前任的帧**（渲染串台）：推流器原先在拿会话锁**之前**
   就挂上，于是第二个 turn 在门外排队时已"在听"，先收到上一个 turn 的收尾帧。
   修法：`ask` 增加 `on_started` 回调，拿到锁之后才挂。
3. **刷新后待审批卡片回不来**（turn 白等 300 秒后 fail-closed）：后端一直有
   `GET /api/approvals`（注释写着"刷新后也能补看到"），**前端从没调过**。修法：
   接回时补看；`PendingApproval` 带上 `session`，跨会话时改用横幅 +
   「切过去处理」（画在当前会话里会让人以为"这条对话在等我批准"）。

## 已知边界（诚实记录）

1. **界面依赖是可选的**：这意味着"忘了装 sessions"不会在装载期报错，而是打开
   页面才看到 503。这是刻意的取舍（界面要能在换插件时活着）；`boot.py` 的组合里
   两者总是一起出现，实际影响为零。
2. **静态白名单要手工维护**：新增页面资源（图片、字体）得往 `STATIC_FILES` 加一行。
   这是"绝不路径拼接"付的小代价。
3. **turn 不再随请求结束而结束**：客户端断开（含刷新）后 turn 会跑完——这是"刷新
   不掉进度"的实现方式，代价是"人走了，账单还在涨"（要真停得按中断）。
4. **工具调用不可中断**：协作式取消要等正在执行的 shell 返回（半截命令比等几秒更糟）。
5. **同会话不排队**：第二条消息要么等它跑完、要么中断它，没有第三条路。
6. **流式请求不复用连接**（`Connection: close`）：每次流式新建一条 TCP，本机可忽略。
7. **单个 turn 内疯长压不动**：几百次工具往返把上下文撑爆时，压缩区够不到
   当前 turn（折掉正在干的事会让模型当场失忆）。这类"单个巨大工具结果"是
   `_07`（大结果搬运）的题目。
8. **压缩必然打断一次前缀缓存**：摘要进请求意味着前缀变了，下一次调用全 miss。
   这正是"90% 才压、压完落在 15%~20%"的价值——把打断次数压到最低。
9. **摘要有损**：所以尾巴留 10% 原版；且摘要被要求保留"目标/决定/路径/待办"四类。
10. **估算不是 tokenizer**：中文/其他按 0.6/0.3 估算，触发判断有误差；
    实测一侧（`prompt_tokens`）在真实 provider 下会持续纠正它。
