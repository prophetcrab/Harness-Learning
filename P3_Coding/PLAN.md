# P3 阶段计划（`_01`–`_10`）

P3 的组织方式沿用 P2：**每个阶段一个自包含目录，只加一个机制**——
`_0N` 从 `_0(N-1)` 的完成态复制起步，加完一个能力再进下一阶段。
区别是 P3 的底座已经成型（`mini_harness/` = 插件内核 + 九插件基线），
所以阶段目标是**在插件底座上补常规 harness 能力**，而不是再造骨架。

## 三条排期规则

1. **`mini_harness/` 是基线快照**（v0.3，插件化的九插件形态）。阶段目录从它
   （或上一阶段完成态）复制起步；里程碑处把最新阶段重生成回整合包（同 P2 决策 0019）。
2. **垂类未定**：`_01`–`_04` 与垂类无关，可立即开工；`_05` 起按垂类裁剪——
   不用的阶段直接划掉，不要"全都要"。
3. **每阶段纪律**：一个机制、四件套（README / 入口 / 测试 / 启动器）、
   决策记录、门禁绿（ruff + pytest）、不通过不前进。**测试文件名带阶段前缀**
   （`test_s0N_*`），避免与基线/其它阶段在全量跑时同名冲突（P2 的纪律，此处沿用）。

## 阶段一览

| 阶段 | 加什么（一个机制） | 验收形状（要点） | 依赖垂类 | 状态 |
|---|---|---|---|---|
| `_01_Self_Plugin_Tools` | **自扩展工具**：`list_plugins` / `load_plugin` / `unload_plugin` 三个工具，模型可操作自身插件；白名单限定、装卸需审批、fail-closed | 模型能列出台账；装/卸白名单插件生效且留下日志事件；白名单外被拒；卸载后工具面即时变化 | 否 | ✅ 完成（2026-10-14；决策 0023） |
| `_02_Streaming` | **流式输出**：provider 增加 `stream()`，chunk 以 `llm/stream` 事件流出、循环聚合为完整响应；支持中途取消 | FakeLLM 剧本支持 chunk 帧；同一套循环测试在流式/非流式下全绿；界面逐字显示 | 否 | ☐ |
| `_03_Usage_Budget` | **用量与预算**：累计 token 用量（按 turn / 按会话）、预算上限、超限结构化收尾 | 用量累计正确（FakeLLM 指定 usage）；超限返回结构化状态；事件里可观测 | 否 | ☐ |
| `_04_Compaction` | **上下文压缩**：超阈值时把旧区段摘要成一条消息；日志用"遮蔽"实现，绝不改写历史 | 压缩后投影变化、日志原样；重放仍然同构 | 否 | ☐ |
| `_05_Tasks` | **任务管理**：`todo` 工具（增/列/完成）+ goal 状态进日志 | 跨 turn 任务清单持久；投影一致；resume 后还能看到 | 是 | ☐ |
| `_06_Spill` | **大输出转存**：工具结果超限转存文件、给模型引用句柄（可 read 回来） | 超大结果不炸日志；句柄可读回；截断/转存有上限 | 是 | ☐ |
| `_07_Guard` | **护栏**：重复工具调用提醒、空转检测（对齐 dsh 的 repeat-tool-reminder） | 重复 N 次触发提醒事件；提醒进模型历史；不误伤正常重试 | 是 | ☐ |
| `_08_Credentials` | **凭证服务**：集中管理 key，工具与 shell 从凭证服务取；子进程继续剥除敏感变量 | key 不出现在模型可见处；shell 读不到；换 key 不改工具代码 | 是 | ☐ |
| `_09_Subagent` | **子代理**：`task` 工具派生独立会话的子代理，结果摘要回填父会话；并发与预算受控 | 子代理有自己的 session id 与日志；父只看摘要；父子事件流可关联 | 是 | ☐ |
| `_10_Skill_MCP` | **技能与 MCP**：技能目录（模型按需加载操作手册）+ 接入一个外部 MCP server 的工具面 | 技能被模型发现并按需加载；MCP 工具出现在工具面并可用 | 是 | ☐ |

## 说明

- **顺序逻辑**：`_01` 是 P3 的特色（自扩展），先做；`_02`/`_03`/`_04` 是
  "模型调用链"的三大基础补强，做完这三项，P3 的 agent 才算"能长期用"；
  `_05` 起进入任务/工程化能力，按垂类取舍。
- **每阶段仍以"插件"形式落地**：新能力优先做成新插件（如 `_09` 的 subagent 插件），
  内核（`kernel/`）除必要机制外不动——保持 P2/P3 立下的"能力进插件"纪律。
- **整合包重生成时机**：`_04` 完成（基础三件套齐）、`_10` 完成（P3 收官）各一次。
- 本文档只定阶段框架；每阶段开工前按项目纪律先细化该阶段的验收标准，
  再写代码（无验收不开始）。
