# P3 阶段计划（`_01`–`_11`）

P3 的组织方式沿用 P2：**每个阶段一个自包含目录，只加一个机制**——
`_0N` 从 `_0(N-1)` 的完成态复制起步，加完一个能力再进下一阶段。
区别是 P3 的底座已经成型（`mini_harness/` = 插件内核 + 能力插件基线），
所以阶段目标是**在插件底座上补常规 harness 能力**，而不是再造骨架。

> **当前状态（2026-10-16）**：`_01`–`_05` 完成（含四轮 `_05` 收尾：三处耦合修复 /
> 壳的两条扩展点 / 插件管理 / turn 执行器）。**`_06` 已按新方向完成**：不是原先
> 计划里的"任务管理"（那两轮均回退，见下），而是**工具插件化**——把工具面拆成
> 底座 + 一件（类）工具一个插件，人可管理、模型可自装（决策 0036–0038）。
> `_07` 及以后尚未开始。`_06` 完成后按用户报告又修了三处（决策 0039：
> 固定端口被多 harness 静默争抢 / 管理面板指纹不匹配导致闪烁 / 被截断的日志
> 投影出孤儿工具结果使会话永久 400）——三处都**回填到 `_05` 与基线**。

## 三条排期规则

1. **`mini_harness/` 是基线快照**（v0.3，完全插件化形态）。阶段目录从它
   （或上一阶段完成态）复制起步；里程碑处把最新阶段重生成回整合包（同 P2 决策 0019）。
2. **垂类未定**：`_01`–`_05` 与垂类无关，可立即开工；`_06` 起按垂类裁剪——
   不用的阶段直接划掉，不要"全都要"。
3. **每阶段纪律**：一个机制、四件套（README / 入口 / 测试 / 启动器）、
   决策记录、门禁绿（ruff + pytest）、不通过不前进。**测试文件名带阶段前缀**
   （`test_s0N_*`），避免与基线/其它阶段在全量跑时同名冲突（P2 的纪律，此处沿用）。

## `_06` 的两次回退与方案改向（重要）

`_06` 做过两轮，都按用户要求撤掉，**当前代码状态 == `_05` 完成态**：

| 轮次 | 做了什么 | 撤掉的原因 |
|---|---|---|
| 第一轮 | **goal 模式**：持久目标（`/goal` 命令 + 目标状态进日志） | 用户："先停止一下，先删掉 goal 模式吧，先做 todo，还是按照文档原本的计划来"（`50921a5` 撤回） |
| 第二轮 | **todo 清单**：`todo` 工具 + `/todo` 人命令 + 整表快照进日志 | 用户："完全回退整个 `_06` 现在 bug 非常严重，正常对话功能都已经无法使用了"（`1a86778` 全部 Revert） |

**教训**（也是之后加做四轮收尾的原因）：两轮的问题都出在**机制穿透了既有链路**——
todo 的快照写入打乱了正常对话的事件流，导致最基本的对话都不能用。回退之后先把
地基欠账补完（耦合修复 / 壳扩展点 / 插件管理 / turn 执行器），再谈新能力。

> **2026-10-16 改向**：用户提出的新方向是**工具插件化**（把工具面拆成底座 +
> 工具插件，可管理、可自装），已按该方向完成 `_06_Tool_Plugins`（决策 0036–0038，
> 406 用例）。原先的"任务管理"**尚未重做**——若要做，仍按下面这条纪律来。
>
> 若要重做"任务管理"：先按纪律把验收标准写细，动代码前**先确认 `_05` 基线 351 用例
> 全绿**，并且新机制必须以插件形式落地、不侵入主循环的事件流。

## 说明

- **顺序逻辑**：`_01` 是 P3 的特色（自扩展），先做；`_02`–`_05` 是
  "模型调用链"的基础补强——**流式 → 用量 → 上下文仪表 → 压缩**：
  先能"看见"（用量、构成、缓存），再"动手"（压缩）——压缩的触发阈值与
  效果评估都依赖 `_04` 的仪表；`_06` 起进入任务/工程化能力，按垂类取舍。
- **每阶段仍以"插件"形式落地**：新能力优先做成新插件（如 `_10` 的 subagent 插件），
  内核（`kernel/`）除必要机制外不动——保持 P2/P3 立下的"能力进插件"纪律。
- **整合包重生成时机**：`_05` 完成（基础四件套齐：流式 / 用量 / 仪表 / 压缩；
  **已于 2026-10-14 重生成**、**2026-10-15 随四轮收尾再次同步**：
  `mini_harness/` = `_05` 完成态含 turn 执行器，351 用例）、
  `_11` 完成（P3 收官）各一次。
- 本文档只定阶段框架；每阶段开工前按项目纪律先细化该阶段的验收标准，
  再写代码（无验收不开始）。
