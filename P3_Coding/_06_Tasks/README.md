# _06_Tasks —— 任务清单（整表快照进日志，/todo 人命令）

P3 第 6 阶段（对应 [PLAN.md](../PLAN.md)）。**本阶段只加一个机制**：

> 一个会话级的**任务清单**：模型可以拆步骤、标进度、勾完成；人能用 `/todo`
> 直接管（不花模型的钱）。**清单进日志（整表快照），当前清单由日志折出来。**
> 跨 turn / 重启 / fork 都还在。

**状态：✅ 已完成（2026-10-14）**

## 为什么这样做

**① 整表替换，不是增量。**

每次 `todo_write` 发**完整的新列表**，直接替换旧的。于是：

- 条目**不需要 id**——没有稳定身份可言，反正整张表是快照；
- 折叠简单到只有一条规则：**最后一条赢**（last-write-wins）；
- 模型不必维护"第 2 条是哪个"的索引意识（增量最容易错的地方）。

代价是每次多花一点 token（一张十几条的清单）。**值**——索引错位的代价是
改错条目，那要花的就远不止 token 了。

**② 三条约束，写入前拒绝。**

| 约束 | 为什么 |
|---|---|
| 内容非空、不重复 | 空条目 / 同一条待办出现两次 = 模型没想清楚 |
| **同时最多一条 `in_progress`** | 一次做一件事。多条并行是人的习惯，不是 agent 该学的 |
| 最多 50 条 | 防模型把整个需求文档抄进来 |

约束不满足时**返回错误而不是写半张表**——坏事件会毒死以后每一次重放。

**③ 清单不驱动续跑。**

这是和 goal 类机制的分界线：

    todo    "我想怎么干" —— 执行步骤，模型自己拆，边干边勾
    goal    "你要求干到什么时候" —— 完成条件，驱动自动续跑

如果清单也能续跑，模型随手列个十步计划就等于给自己签了一张十轮的支票。
持续推进的职责该归 `goal` 那样的机制（PLAN 里原本把两者写在同一个阶段，
实现时按"一个阶段一个机制"拆开了：只有 todo 落在本阶段）。

**④ 人命令带序号，模型不带。**

`/todo done 2` 比 `/todo done 把文档里所有失败的检查项修好` 快得多——清单短，
人一眼看得到第几条。**但模型侧不给序号**：它必须发整表，因为它不该维护索引。

## 怎么用

```bash
cd P3_Coding/_06_Tasks
python -m pytest -q

# REPL
python chat.py
你：/todo 读需求             # ★ 直接写内容就加一条（不用打 add）
你：/todo 写代码
你：/todo                    # 看清单（带序号）
你：/todo doing 2            # 第 2 条开始做
你：/todo done 2             # 勾掉

# 网页：输入框敲 / → 菜单选 /todo → 补全成 "/todo " → 接内容
#       右上角有常驻面板显示清单（模型或你自己改的都实时反映）
```

模型侧一个工具：`todo_write`（发完整清单）。

## 验收（对照 PLAN.md）

- [x] **跨 turn 持久**：清单在多个 turn 之间存活
- [x] **投影一致**：`fold_todos(日志)` == 服务读到的清单（硬断言）
- [x] **resume 后还能看到**：重新装配打开同一会话，清单逐字相同且可继续改
- [x] 整表替换（写三次得到的是第三次的表，不是累加）
- [x] 三条约束逐条验证；违规返回 `{"error": ...}` 而不是炸掉 turn
- [x] 坏日志（两条 in_progress / 状态非法 / 重复条目）折叠时当场报错
- [x] **不驱动续跑**：写清单不产生额外轮次（钉住的回归断言）
- [x] 人命令：序号、内容、包含匹配（多条匹配要求用序号）、中文别名、打错不炸
- [x] 模型写清单进**当前会话**（不是 default）；卸载插件即回卷

## 踩到的坑

**同名会话有两个 `Session` 对象**（`plugins/sessions.py`）。

`open()` 起初每次新建实例，于是 agent 与清单存储各拿一份**内存副本**：一方
append 的事件另一方在内存里永远看不到（磁盘上其实写了），于是清单读不出来。
修法是按 session_id 缓存实例——**日志是唯一真相，真相的句柄也应当唯一**。

（这个 bug 在做 goal 原型时先被踩到；goal 撤销后修复保留了下来，
因为 todo 同样要"两个消费者读同一份活日志"。）

顺手还补了 `webui/index.html` 缺失的 `#banner` 元素——`showBanner` 被四处
调用却从无此元素，那些路径一执行就抛错（`/todo` 用 banner 显示结果才暴露）。

## 已知边界（诚实记录）

1. **清单是"模型的工作记忆"，不是硬性计划**：模型可能不按它执行，也可能中途
   重写整张表。约束只能保证"格式对、单条在做"，保证不了"说到做到"。
2. **不做依赖关系**（没有前后置、没有优先级）：真需要的话那是另一个机制，
   dsh 的 todo 也只有 content + status 两样。
3. **超长清单只能靠 50 条上限兜**——不做分页/折叠。
